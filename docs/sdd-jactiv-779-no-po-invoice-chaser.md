## 1. API Workflow Overview

Unattended API Workflow running weekdays at 10:00 EET/EEST (org architectural considerations §1). Queries Coupa for draft/new invoices dated within past 7 days, filters to exclude credit notes and invoices with linked POs, counts qualifiers, and sends Slack Block Kit message to WLX9BD8FN if count > 0; otherwise exits cleanly (BR-07).

**Trigger:** Orchestrator weekday schedule.  
**Outcome:** Slack message when count > 0; no message when count = 0.

## 2. Input Schema

The workflow is triggered by Orchestrator and accepts no inputs.

| Parameter | Type | Required | Purpose |
|---|---|---|---|
| (none) | — | — | Trigger runs on schedule; no input arguments. |

## 3. Output Schema

| Property | Type | Semantics |
|---|---|---|
| `status` | string | Literal value `"Successful"` on completion. |
| `qualifying_count` | number | Count of invoices without a linked PO (may be zero). |
| `slack_sent` | boolean | True if Slack message posted; false if count was zero. |

**Business Rules Enforcement:**

| Rule | Step(s) | Enforced by |
|---|---|---|
| BR-01, BR-02 | 7 | Filter checks po-number or order-header-num in invoice-lines; excludes description-only PO. |
| BR-03 | 7 | Filter excludes type=Credit Note. |
| BR-04 | 6 | Coupa query filters status[in]=draft,new and date window. |
| BR-05 | 11, 14 | Slack message carries count only; no invoice list. |
| BR-06 | 11, 14 | Message includes policy note, action request, filtered Coupa URL to WLX9BD8FN. |
| BR-07 | 10 | If count=0, skip Slack; exit cleanly. |
| BR-08, BR-09 | all | No retry; failed run sends no Slack. |
| BR-10 | design | Workflow reads Coupa only; no create/modify. |

## 6. Error Handling

| Failure | Detection | Response |
|---|---|---|
| S1 — Coupa unavailable | statusCode != 200 or timeout | Log, throw, fail. No retry (BR-08). No Slack (BR-09). |
| S2 — Slack delivery failure | response.ok != true | Log, throw, fail. |
| S3 — Timeout | No response within window | Log, throw, fail. |
| S5 — Credential expiry | 401/403 auth | Log, alert, fail. |
| S6 — Unhandled exception | Script error | Log stack, fail. |
| B3 — Clean day | count = 0 | Exit cleanly; no error, no message. |

Single try/catch boundary; no per-call handlers.

## 8. Testing Strategy

### Happy Path

| Case | Expected |
|---|---|
| Clean day (B3) | count=0, slack_sent=false. No Slack message; job succeeds. |
| With qualifiers | count=3, slack_sent=true. Slack posted to WLX9BD8FN; title shows count; Coupa URL button present. |

### Business Exceptions

| Case | Expected |
|---|---|
| B1 — Credit note | Excluded; reason logged. |
| B2 — Description PO | Treated as missing; counted in Slack. |

### System Errors

| Case | Expected |
|---|---|
| S1 — Coupa fail | Job fails; error logged. |
| S2 — Slack fail | Job fails; error logged. |
| S5 — Auth fail | Job fails; credential alert to Orchestrator. |
| S6 — Unhandled | Job fails; full stack logged. |

Target: < 2 min per run (~194 invoices). No retry loops (BR-08).
